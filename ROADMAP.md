# Дорожная карта

Синтаксис из коробки и готовые расширения. Ядро рисует по смыслу всё, что узнаёт Markdig, и HTML,
который встречается в README. Популярный синтаксис других программ живёт в той же библиотеке
готовыми расширениями: по умолчанию они выключены и подключаются наборами одной строкой. Чужих
библиотек нет; возможности с чужими библиотеками описаны идеями в [`docs/ideas/`](docs/ideas/).

Каждый пункт закрывается тестами, образцом в витрине и вики на двух языках. Новый вид блока
проходит все места разом — правило «Свой синтаксис — расширением, а не правкой библиотеки» в
[`Markdig.Wpf.Viewer/AGENTS.md`](Markdig.Wpf.Viewer/AGENTS.md). Новые термины — в глоссарий.

## Этап 2. Ядро: новые виды блоков

- [ ] **Плашка** — вид блока для выделенных блоков: вид плашки, заголовок, вложенные блоки,
  сворачиваемость. На ней стоят плашки GitHub и готовые расширения. Цвет и значок вида — ключами
  темы, заголовки видов — ключами подписей, по умолчанию английскими.
- [ ] **Плашки GitHub** `> [!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, `[!CAUTION]`. Markdig
  их уже разбирает (`AlertBlock`), вьюер рисует плашкой; в разметку выделенного — тем же
  синтаксисом.
- [ ] **Сворачиваемый блок** — вид блока с заголовком и вложенными блоками. Свёрнутость —
  состояние, которое переживает виртуализацию и новый текст. На нём стоят `<details>` (этап 3) и
  готовые расширения.
- [ ] **Списки определений** — вид блока «термин — определения», шаблон и ключи темы; в разметку
  выделенного — тем же синтаксисом.
- [ ] **Front matter.** `UseYamlFrontMatter` — в стандартной настройке разбора. Блок между строками
  `---` в начале документа не рисуется, позиции строк исходника не сдвигаются, его текст без
  разбора отдаёт свойство вьюера. Разбор YAML — дело приложения.

## Этап 3. Ядро: HTML из README

Теги разбирает свой разбор (`HtmlTag`), без HTML-библиотек; неузнанное остаётся текстом, как
сейчас.

- [ ] **`<details>` и `<summary>`** — сворачиваемый блок этапа 2; `open` — развёрнут сразу.
  Markdown между тегами рисуется как обычно.
- [ ] **Выравнивание** — `<p align="center|right">` и `<div align="…">` выравнивают своё
  содержимое: картинки и текст.
- [ ] **Картинки HTML-блоком** — `<img>` отдельной строкой, `<a href><img></a>` — картинкой-ссылкой,
  `<picture>` — по своему `<img>`; `<br>` внутри блока — перенос.
- [ ] Список узнаваемых тегов — на странице вики «Что рисуется».

## Этап 4. API для расширений

- [ ] **Нажатие ссылки из своего виджета** — публичный метод и команда для шаблонов. Путь тот же,
  что у ссылки в тексте: событие `MarkdownLink.Navigate`, якорь документа, открыватель ссылок.
- [ ] **Оформленный текст** — кусок текста с именем оформления. Он остаётся текстом карты:
  выделяется кусками, находится поиском, переносится. Вид — стиль `Span` из темы по имени
  оформления; в разметку выделенного — обрамлением, которое задаёт расширение.
- [ ] **Несколько инлайнов из одного узла** — новый член `MdExtension` с реализацией по умолчанию
  через `ConvertInline`: сигнатуру `ConvertInline` менять нельзя, это контракт пакета.
- [ ] **Набор расширений** — расширение из нескольких расширений: опрашивает их по порядку,
  настройки — своими свойствами. `Extensions` принимает наборы вперемешку с одиночными
  расширениями; подключение — одной строкой в XAML или в коде.
- [ ] **Готовые расширения в библиотеке** — папка и пространство имён `Kit`, в XAML — один префикс.
  Шаблоны и ключи `Md.<Расширение>.*` — в теме библиотеки, подписи — ключами.
- [ ] **Правило в `Markdig.Wpf.Viewer/AGENTS.md`**: готовые расширения пользуются только публичным
  API — так же, как расширения приложения.

## Этап 5. Расширения: плашки и сворачиваемое

- [ ] **Плашки Obsidian** `> [!вид] Заголовок` — любые виды: известные — со своим цветом и
  значком, незнакомые — как заметка. Свой заголовок после вида; `-` и `+` после вида — плашка
  сворачивается, `-` — свёрнута сразу.
- [ ] **Предупреждения MkDocs** `!!! вид "Заголовок"` с содержимым под отступом в четыре пробела;
  `???` — свёрнутое, `???+` — развёрнутое сворачиваемое. Свой разборщик блоков Markdig.
- [ ] **Контейнеры `:::вид`** Docusaurus, VuePress и HackMD — известные имена плашкой, `details` и
  `spoiler` — сворачиваемым блоком; заголовок — после имени.

## Этап 6. Расширения: связи

Смысл задаёт приложение. Щелчок уходит путём ссылок с целью `wiki:…`, `tag:…`, `mention:…`, а
есть ли страница и как зовут человека, расширение спрашивает у резолвера — интерфейса, который
реализует приложение.

- [ ] **Вики-ссылки** `[[Страница]]`, `[[Страница#Раздел]]`, `[[Страница|подпись]]` — ссылка
  оформленным текстом; страница, которой по резолверу нет, — своим видом. Разборщик стоит раньше
  обычных ссылок и позже оглавления.
- [ ] **Встраивание картинок** `![[файл.png]]` — картинка через загрузчик картинок вьюера.
- [ ] **Теги** `#тег`, `#тег/вложенный` — чипом. Не тег: одни цифры, решётка после буквы или
  цифры (`C#`), решётка внутри ссылки или кода.
- [ ] **Упоминания** `@имя` — чипом или ссылкой. Не упоминание: `@` после буквы или цифры (почта).
  Отображаемое имя — от резолвера.
- [ ] **Ссылки на задачи по шаблону** — `#123`, `org/repo#45`, `PROJ-45` становятся ссылками по
  шаблонам приложения: префикс и номер — адрес задачи. По умолчанию шаблонов нет. Решётка с одними
  цифрами — задача, а не тег.
- [ ] **Оглавление на месте** — абзац ровно из `[TOC]`, `[[_TOC_]]` или `[[toc]]` становится
  оглавлением из заголовков документа: пункт прокручивает к заголовку, список обновляется вместе с
  текстом.

## Этап 7. Расширения: чипы и работа над текстом

- [ ] **Чипы** `::текст::` с видом классом: `::текст::{.вид}`. Markdig уже разбирает строчные
  контейнеры и прикрепляет к ним класс; цвета видов — ключами темы.
- [ ] **Цветовые чипы** — код в строке, который целиком является цветом (`#RGB`, `#RRGGBB`,
  `#RRGGBBAA`, `rgb()`, `rgba()`, `hsl()`, `hsla()`), получает кружок этого цвета рядом с кодом.
- [ ] **CriticMarkup** `{++…++}`, `{--…--}`, `{~~…~>…~~}`, `{==…==}`, `{>>…<<}` — правки оформленным
  текстом, комментарий — значком с подсказкой. Разборщик стоит раньше выделений Markdig, которые
  сейчас портят эту запись.
- [ ] **Принять и отклонить правку** — событие с местом правки в исходнике и текстом после решения;
  текст правит приложение, как с флажками задач.
- [ ] **Комментарии** `%%…%%` — внутри строки и блоком на несколько строк; не рисуются.
- [ ] **Спойлеры** `||…||` — текст закрашен, пока по нему не щёлкнут: оформленный текст,
  раскрытость — состояние. Внутри ячейки таблицы `|` делит ячейки, там спойлер не работает.
- [ ] **Статусы задач** `- [/]`, `- [-]`, `- [>]`, `- [?]`, `- [!]` — значок вместо флажка; щелчок
  поднимает `TaskToggled`, как у обычной задачи, статус — в аргументах события.
- [ ] **Сноски подсказкой** — готовое расширение по примеру из вики: ссылка на сноску показывает её
  текст подсказкой, определение не рисуется.

## Этап 8. Расширения: медиа и данные

- [ ] **Карточки видео** — картинка-ссылка на YouTube, Vimeo, RuTube становится карточкой: превью
  через загрузчик картинок, название из alt, значок воспроизведения; щелчок — путём ссылок.
  Загрузку превью из сети можно выключить.
- [ ] **Эмодзи-шорткоды** `:smile:` — расширение Markdig без замены смайликов вида `:)`.
  Одноцветность эмодзи в WPF — в вики.
- [ ] **Шорткоды** `{%имя аргументы%}` и `{{< имя аргументы >}}` — виджет по имени из реестра.
  Библиотека регистрирует youtube и vimeo — карточками видео, gist и pdf — карточками-ссылками,
  toc — оглавлением на месте; приложение регистрирует свои имена со своими виджетами.
- [ ] **Таблицы из CSV** — блок кода с языком `csv` или `tsv` рисуется таблицей: первая строка —
  заголовок, значения в кавычках — по правилам CSV.
- [ ] **Карточка свойств** — front matter таблицей «ключ — значение» в начале документа. Разбор
  только для показа: `ключ: значение`, списки `[a, b]`, вложенное — текстом. Разобранные данные
  наружу не отдаются: это дело приложения.

## Этап 9. Наборы

Порядок расширений внутри набора задаёт библиотека: записи спорят за одни знаки, и раньше разбирает
тот, кто стоит раньше. Настройки — свойствами набора: резолверы, выключение частей.

- [ ] **GitHub** — упоминания, ссылки на задачи, цветовые чипы, эмодзи, карточка свойств.
- [ ] **GitLab** — ссылки на задачи, цветовые чипы, оглавление, эмодзи.
- [ ] **Obsidian** — вики-ссылки, встраивание картинок, теги, плашки Obsidian, комментарии,
  статусы задач, карточка свойств.
- [ ] **MkDocs** — предупреждения.
- [ ] **Docusaurus** — контейнеры `:::`; годится и для VuePress.
- [ ] **HackMD** — контейнеры `:::`, оглавление, шорткоды.
- [ ] **Чат** — упоминания, спойлеры, эмодзи.

## Этап 10. Документация

- [ ] **Вики** — рубрика «Готовые расширения»: страница на каждый набор и на каждую тему
  расширений, синтаксис каждого расширения, подключение одной строкой; на странице «Что рисуется» —
  новое в ядре. На обоих языках, снимки — пробником.
- [ ] **README** — готовые расширения и наборы в списке возможностей.
- [ ] **Витрина** — вкладка с наборами: документ в синтаксисе каждого диалекта и переключатель
  наборов.
