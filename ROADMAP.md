# Дорожная карта

## Разбор REVIEW.md и подготовка к публикации

Баги из разбора библиотеки, четыре пункта из его раздела «Чего не хватает» — недоверенный текст,
перенос в таблицах, картинки, разбор вне потока интерфейса — и подготовка пакета: новое имя
`Beresta.Markdown.Wpf`, иконка, настройка пакета, версия 0.7.0, XML-доки на двух языках, несколько
версий .NET.

Каждый баг сначала закрепляется тестом, который на текущем коде красный. Изменение поведения
отражается в вики на обоих языках.

Вне этой работы и в бэклог не идут: мягкий перенос строки, размер шрифта от приложения, незнакомый
HTML, клавиатура, флажки задач, тёмная тема.

### Этап 1. Падения и утечки

- [x] Общая коллекция расширений не держит вьюеры: подписка на её изменения слабая.
- [x] Своя коллекция вьюера и общая не смешиваются: `Extensions` — всегда своя, общая задаётся
  отдельным наследуемым свойством, вьюер опрашивает обе. Раздел вики про общие расширения — заново.
- [x] Плашка Obsidian проверяет вид первого блока: не абзац — цитата остаётся цитатой.
- [x] Синхронное исключение загрузчика картинок — неудачная загрузка: виден alt.

Проверка: тесты — 20 вьюеров с общей коллекцией собираются сборщиком мусора; XAML с явным стилем не
дописывает в общую коллекцию; расширение абзацев рядом с `ObsidianCallouts` и бросающий загрузчик не
роняют вьюер.

### Этап 2. Разбор и ссылки

- [ ] Настройка разбора не теряется с расширениями: вьюер принимает настройку построителя
  (`Action<MarkdownPipelineBuilder>`) рядом с готовым конвейером; `DisableHtml()` и подобное
  работают и с расширениями.
- [ ] HTML в буфере обмена — тем же конвейером, что и разбор: HTML-рендереры готовых расширений
  вызываются.
- [ ] Почтовая автоссылка `<user@example.com>` — цель `mailto:user@example.com`.
- [ ] Ссылка на заголовок по его тексту `[My Heading]` — ссылка, цель из `GetDynamicUrl`.
- [ ] Код и клавиша внутри ссылки, жирного, зачёркнутого, оформления расширения получают их: ссылка
  остаётся ссылкой, в том числе для Tab.

Проверка: тесты на каждый пункт; `DisableHtml()` с `Tags` оставляет `<b>bold</b> text` текстом.

### Этап 3. Таблицы

- [ ] Ячейка-добивка короткой строки — со своим списком инлайнов: карта не путает её с соседними,
  пометки строк и две панели на таких таблицах верны.
- [ ] Шапка таблицы — по `TableRow.IsHeader`: сетка без `+===+` шапки не получает; объединённые
  ячейки сетки (`ColumnSpan`) занимают свои столбцы.
- [ ] Таблица укладывается в ширину вьюера: столбцы делят ширину по содержимому, текст ячеек
  переносится; горизонтальная прокрутка — только когда не помещается и самое длинное слово.

Проверка: тесты на добивки, шапку и объединённые ячейки; ячейка в 120 слов переносится по ширине
вьюера; снимки таблиц в витрине на обоих языках.

### Этап 4. Смена документа, перерисовка и мелочи

- [ ] Способ сказать вьюеру «это новый документ»: выделение и состояния виджетов не переезжают в
  чужой текст; правка того же документа ведёт себя как сейчас.
- [ ] `Refresh()`: вьюер заново собирает тот же текст, спрашивая резолвер, шаблоны ссылок на задачи
  и обработчики шорткодов; выделение и состояния виджетов остаются.
- [ ] Потеря захвата мыши посреди протаскивания останавливает автопрокрутку и выделение.
- [ ] Подчёркивание сокращения перекрывается ключом темы и следует смене темы.
- [ ] В `AGENTS.md` библиотеки выделение описано, каким оно есть: мышью и Ctrl+A.

Проверка: тесты — новый документ сбрасывает выделение и свёрнутость, правка сохраняет; после
`Refresh()` ссылка на появившуюся страницу перестаёт быть «нет такой», а свёрнутое остаётся
свёрнутым; потеря захвата останавливает таймер; перекрытый ключ подчёркивания виден.

### Этап 5. Картинки

- [ ] Неудачная загрузка не запоминается: картинка, появившаяся позже, и временный сбой сети
  загружаются снова.
- [ ] Декодирование не больше нужного размера: большая картинка уменьшается при декодировании.
- [ ] Кэш картинок ограничен памятью, а не числом адресов.
- [ ] Загрузка отменяется, когда её картинку больше никто не ждёт.

Проверка: тесты — повтор после неудачи, размер декодированной картинки, вытеснение по памяти, отмена
ушедшей загрузки.

### Этап 6. Недоверенный текст

- [ ] Политика загрузки картинок: разрешённые схемы и хосты, режим без сети, запрет сетевых путей
  `file://` и UNC; удобная готовая настройка для чата и ответа модели.
- [ ] Страница вики о показе недоверенного текста на обоих языках: чем грозят картинки, как
  настроить загрузку, что уже защищено у ссылок.

Проверка: тесты — запрещённые схемы, хосты и сетевые пути не загружаются, загрузчик не вызывается.

### Этап 7. Разбор вне потока интерфейса

- [ ] Большой текст разбирается в фоне и ложится правками в потоке интерфейса; порог — свойство
  вьюера, маленький текст разбирается сразу, как сейчас.
- [ ] Быстрые правки схлопываются: устаревший разбор отбрасывается, на экране остаётся последний
  применённый текст.
- [ ] Поток текста, две панели, синхронная прокрутка и разметка выделенного работают с фоновым
  разбором.

Проверка: тесты — порядок применения, схлопывание, поведение маленького текста не меняется; замер на
большом документе — только с разрешения пользователя.

### Этап 8. Новое имя — Beresta.Markdown.Wpf

- [ ] Проекты, папки, решение, сборки, корневое пространство имён: `Beresta.Markdown.Wpf`,
  `.Showcase`, `.Tests`; пути `pack://` к теме, `clr-namespace` в разметке, скрипты в `tools/`.
- [ ] README, вики и агентские файлы — с новым именем, примеры подключения тоже.
- [ ] Адрес репозитория — `github.com/porohkun/Beresta.Markdown.Wpf`: пакет, README, вики, витрина,
  `.gitmodules`.

Проверка: сборка, тесты, витрина и снимки вики на обоих языках.

### Этап 9. Пакет

- [ ] Иконка `icon512.png`: иконка пакета, окна и exe витрины, шапка README и вики.
- [ ] Пакет собирается: README внутри пакета (NU5039), зависимость от Markdig объявлена — без
  `SuppressDependenciesWhenPacking`, символы и Source Link, описание и метки для поиска. Закрывает

- [ ] Версия 0.7.0: четыре свойства в csproj и заголовки README.

Проверка: `dotnet pack` без ошибок и предупреждений; содержимое пакета — сборка, README, иконка,
зависимость от Markdig.

### Этап 10. XML-доки на двух языках

- [ ] Доки публичного API в коде — по-английски, русский перевод — отдельным файлом в формате
  компилятора. В пакете английские — основной файл рядом со сборкой, русские — в папке `ru`.
- [ ] Доки внутренних членов остаются по-русски и в файл пакета не попадают.
- [ ] Тест сверяет русский файл с публичным API: перевод есть у каждого публичного и защищённого
  члена, лишних нет.
- [ ] Правило про XML-доки в `AGENTS.md` — под два языка.

Проверка: сборка без предупреждений о недостающих доках; тест сверки; в пакете у каждой целевой
платформы английский файл рядом со сборкой и русский в `ru`, в обоих только публичный API.

### Этап 11. Версии .NET

- [ ] Пакет под все версии .NET, которые собираются сразу или с минимальными правками; что требует
  больше — не входит.
- [ ] Тесты проходят на каждой вошедшей версии; вики и README называют поддерживаемые версии.

Проверка: `dotnet pack` с несколькими целевыми платформами, тесты на каждой.
