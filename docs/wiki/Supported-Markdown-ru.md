[English](Supported-Markdown) | **Русский**

Вьюер разбирает текст Markdig: CommonMark и расширенный набор расширений Markdig
(`UseAdvancedExtensions()`) — таблицы, списки задач, сноски, идентификаторы заголовков, автоссылки,
атрибуты, свои контейнеры и другое, — а также front matter (`UseYamlFrontMatter()`). Всё, что узнал
разбор, попадает на экран: конструкция без своего вида показывается своим содержимым или исходным
текстом. Молча ничего не пропадает.

![Почти весь синтаксис в одном документе](images/overview.png)

## Блоки

| Markdown | На экране |
|---|---|
| `# Heading` … `###### Heading`, подчёркивание `===` или `---` | шесть уровней заголовков |
| абзац | текст с переносом слов; перенос строки в исходнике — перенос строки на экране |
| `> quote` | черта слева; внутри любые блоки |
| `> [!NOTE]`, `> [!TIP]`, `> [!IMPORTANT]`, `> [!WARNING]`, `> [!CAUTION]` | плашка: черта, значок и заголовок цвета её вида — см. ниже |
| `- item`, `* item`, `1. item`, `7) item` | маркеры по уровню вложенности (`•`, `◦`, `▪`), номера от первого пункта |
| `a. item`, `A. item`, `i. item`, `I. item` | буквы и римские цифры, тоже от первого пункта: `c.` начинается с c |
| `- [ ] task`, `- [x] task` | флажок перед пунктом — см. [Списки задач](Task-Lists-ru) |
| термин и `:   определение` на следующей строке | список определений — см. ниже |
| ```` ```lang ```` код в ограждении | блок кода с шапкой языка — см. [Блоки кода](Code-Blocks-ru) |
| код с отступом в четыре пробела | блок кода без шапки |
| `\| a \| b \|` со строкой `\|---\|---\|` | таблица со строкой заголовка; `:---`, `:---:` и `---:` выравнивают столбцы |
| сетка-таблица, нарисованная `+---+` и `\|` | таблица, в ячейке которой может быть несколько абзацев, список или код |
| `---`, `***` | горизонтальная черта |
| `[^1]: text` | определение сноски — см. ниже |
| `^^^` … `^^^ Подпись` | фигура: содержимое по центру и подпись под ним |
| `^^ текст` | подвал мелким текстом |
| `:::name` … `:::` | свой контейнер: показывает содержимое; [расширение](Extensions-ru) может нарисовать его по-своему |
| `---` … `---` в самом начале документа | front matter: ничего — см. ниже |
| HTML-блок | по смыслу, если вьюер знает все его теги, — см. [HTML из README](#html-из-readme); иначе его исходный текст |
| `<!-- comment -->` | ничего |

## Внутри строки

| Markdown | На экране |
|---|---|
| `**bold**`, `*italic*`, `***both***` | жирность и наклон |
| `~~strike~~` | зачёркивание |
| `H~2~O`, `x^2^` | нижний и верхний индекс |
| `==marked==` | фон маркера |
| `++inserted++` | подчёркивание |
| `""Название произведения""` | своим начертанием, по умолчанию курсивом |
| `*[HTML]: HyperText Markup Language` | каждое «HTML» в документе получает подсказку с расшифровкой; само определение не показывается |
| `` `code` `` | код в рамке |
| `[text](https://example.com "title")` | ссылка; заголовок — её подсказка, см. [Ссылки и якоря](Links-and-Anchors-ru) |
| `<https://example.com>`, `www.example.com` | ссылки |
| `![alt](picture.png)` | картинка — см. [Картинки](Images-ru) |
| `[^1]` | ссылка на сноску |
| `&copy;`, `&laquo;` | знаки © и « |
| два пробела или `\` в конце строки, `<br>` | жёсткий перенос строки |

Строчный HTML: `<b>`, `<strong>`, `<i>`, `<em>`, `<s>`, `<del>`, `<strike>`, `<code>`, `<kbd>`,
`<sub>`, `<sup>`, `<mark>`, `<ins>`, `<u>`, `<cite>`, `<a href="…" title="…">`,
`<img src="…" alt="…" width="…" height="…">` и `<br>` рисуются как их аналоги из Markdown;
`<kbd>` — клавишей. Другие теги показываются текстом.

**Любой `.md`-файл**:

```markdown
Press <kbd>Ctrl</kbd>+<kbd>C</kbd> to copy. Water is H<sub>2</sub>O, the area is 5 m<sup>2</sup>.
```

## HTML из README

В README немного HTML берут для того, чего не умеет Markdown: логотип по центру, ряд значков,
сворачиваемый раздел. Такие HTML-блоки вьюер рисует по смыслу, как GitHub.

| HTML | На экране |
|---|---|
| `<details>`, `<summary>` | сворачиваемый блок с заголовком из summary; `<details open>` сначала развёрнут |
| `<p align="…">`, `<div align="…">`, `<center>` | содержимое выровнено: `left`, `center`, `right`, `justify` |
| `<h1>` … `<h6>`, в том числе с `align` | заголовки |
| `<img src alt width height title>` | картинка |
| `<a href><img></a>` | картинка-ссылка |
| `<picture>` с `<source>` | картинка из его `<img>` |
| `<br>` | перенос строки |
| `<b>`, `<strong>`, `<i>`, `<em>`, `<s>`, `<del>`, `<strike>`, `<code>`, `<kbd>`, `<sub>`, `<sup>`, `<mark>`, `<ins>`, `<u>`, `<cite>`, `<a href>` | так же, как строчный HTML |

Как на GitHub, Markdown между тегами разбирается, только когда он отделён от них пустыми строками;
текст вплотную к тегам — простой текст, а его пробелы и переносы сливаются в один пробел. HTML-блок с
любым другим тегом — `<table>`, `<span>` — показывается исходным текстом.

**Любой `.md`-файл**:

```markdown
<p align="center">
  <img src="logo.png" width="200" alt="Logo">
  <br>
  <b>My Project</b>
</p>

<details>
<summary>Build from source</summary>

Run `dotnet build` in the repository root.

</details>
```

## Переносы и пустые строки

Вьюер сохраняет форму исходника. Каждая строка исходника начинается на экране с новой строки: мягкий
перенос внутри абзаца рисуется переносом, а не пробелом. Каждая пустая строка между блоками
становится отступом. Документ выглядит как его текст — поэтому с исходником совпадают и
[номера строк](Line-Numbers-ru), и [две панели](Source-Lines-and-Two-Panes-ru).

## Сноски

Определение сноски остаётся там, где написано: в конец документа оно не уезжает. Щелчок по ссылке на
сноску прокручивает к определению, `↩` в определении — обратно к ссылке.

**Любой `.md`-файл**:

```markdown
The viewer is built on Markdig[^parser].

[^parser]: A fast, CommonMark-compliant Markdown parser for .NET.
```

Чтобы показывать сноски по-своему — например, подсказкой у ссылки, — их перекрывают расширением:
[Расширения → Перекрытие встроенного синтаксиса](Extensions-ru#перекрытие-встроенного-синтаксиса).

## Плашки

Цитата, первая строка которой — `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]` или `[!CAUTION]`, —
плашка, как на GitHub: черта, значок и заголовок цвета её вида, внутри любые блоки. Регистр букв вида
не важен. Незнакомый вьюеру вид рисуется заметкой с названием вида в заголовке: `[!kitten]` получает
заголовок «Kitten».

**Любой `.md`-файл**:

```markdown
> [!WARNING]
> The operation cannot be undone.
```

Цвета, значки и заголовки видов — ключи темы, см. [Тему](Theming-ru#все-ключи); заголовки
английские, их переводят как другие [подписи интерфейса](Theming-ru#подписи-интерфейса). Свои
заголовки, сворачивание и больше видов, как в Obsidian и MkDocs, дают
[готовые расширения](Kit-Callouts-ru).

## Списки определений

Термин — своей строкой, его определение — после `:` на следующей строке. Несколько терминов подряд
делят определения под ними, несколько строк с `:` дают несколько определений. Термин рисуется
полужирным, определения — под ним с отступом.

**Любой `.md`-файл**:

```markdown
Markdig
:   A Markdown parser for .NET.

Callout
Admonition
:   A block with the color, icon and title of its kind.
:   The kind is written on the first line of a quote.
```

## Front matter

Front matter — блок между строками `---` в самом начале документа, обычно YAML: заголовок, теги, дата.
Вьюер его не рисует: документ начинается с того, что идёт после него, а номера строк исходника его
строки по-прежнему учитывают. Текст блока без разбора — в свойстве `FrontMatter`; нет блока — `null`.
Разбор YAML — дело приложения.

**`MainWindow.xaml.cs`**, после того как задан текст:

```csharp
Viewer.Markdown = "---\ntitle: Release notes\n---\n\n# 0.6.0";
string? yaml = Viewer.FrontMatter; // "title: Release notes"
```

`FrontMatter` — свойство зависимости только для чтения: меняется с каждым новым текстом, к нему можно
привязаться.

## Своя настройка разбора

`MarkdownPipeline` заменяет стандартную настройку разбора Markdig — например, чтобы выключить
синтаксис. [Расширения](Extensions-ru) вьюера добавляются поверх неё. Стандартная настройка —
`UseAdvancedExtensions()` и `UseYamlFrontMatter()`: без второго front matter читается как обычный
Markdown и превращается в черту и заголовок.

**`MainWindow.xaml.cs`**, в конструкторе (`using Markdig;`):

```csharp
Viewer.MarkdownPipeline = new MarkdownPipelineBuilder()
    .UsePipeTables()
    .UseTaskLists()
    .Build();
```

## Типографские замены

SmartyPants заменяет знаки пишущей машинки типографскими: прямые кавычки — парными, `--` и `---` —
тире, `...` — многоточием, `<<` и `>>` — «ёлочками». По умолчанию выключен: в технических текстах он
превратил бы `--force` в «–force». Включается своей настройкой разбора; оттуда же берётся и таблица
замен, её значения — HTML-сущности.

**`MainWindow.xaml.cs`**, в конструкторе (`using Markdig; using Markdig.Extensions.SmartyPants;`):

```csharp
var typography = new SmartyPantOptions();
typography.Mapping[SmartyPantType.LeftDoubleQuote] = "&laquo;";
typography.Mapping[SmartyPantType.RightDoubleQuote] = "&raquo;";

Viewer.MarkdownPipeline = new MarkdownPipelineBuilder()
    .UseAdvancedExtensions()
    .UseSmartyPants(typography)
    .Build();
```

С такой таблицей `"Цитата"` показывается как «Цитата».
