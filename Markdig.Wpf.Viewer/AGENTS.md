# Markdig.Wpf.Viewer

Библиотека, которая уходит в пакет: вьюер `MarkdownViewer`, разбор markdown в модель блоков, тема
по умолчанию и перехват ссылок.

Общие правила кода, документации и комментариев — в [корневом `AGENTS.md`](../AGENTS.md).

## Зависимости

WPF и пакет Markdig. На проекты решения не ссылается.

## Состав

| Часть | Что это | Где |
|---|---|---|
| Вьюер | контрол: принимает текст и провайдер стилей, держит список блоков | `MarkdownViewer` |
| Разбор | дерево Markdig → вьюмодели блоков и инлайнов | `ModelBuilder` |
| Модель | неизменяемые записи блоков и инлайнов | `ViewModels/`, `Abstractions/` |
| Ссылки | всплывающее событие и команда для своих ссылок | `MarkdownLink*` |
| Презентеры | контролы, которыми шаблоны рисуют блоки | `Presenters/` |
| Панель блоков | раскладка блоков вьюера, создаёт только видимые | `Presenters/MdBlockPanel` |
| Выбор шаблона | провайдер стилей и селектор шаблона по виду блока | `Styling/`, `Abstractions/` |
| Тема по умолчанию | ключи темы, стили блоков, провайдер по умолчанию, стиль вьюера | `Themes/Generic.xaml` |
| Поведения | передача колеса мыши из вложенной прокрутки наружу | `Behaviors/` |

## Markdig дальше разбора не идёт

Дерево Markdig превращается во вьюмодели в `ModelBuilder`, и только там. Вьюмодели — неизменяемые
записи без ссылок на Markdig и WPF; презентеры и шаблоны знают только вьюмодели. В публичном API
Markdig появляется лишь настройкой разбора (`MarkdownPipeline`).

## Новый вид блока проходит все места разом

Запись в `ViewModels/`, ветка в `ModelBuilder`, шаблон в `IMdStyleProvider` и `MdStyleProvider`,
ветка в `MarkdownTemplateSelector`, шаблон и ключи темы в `Generic.xaml`, образец в демо.
Пропущенное место не падает, а молча не рисует блок.

## Публичный API и ключи темы — контракт пакета

Публичные типы и свойства, `IMdStyleProvider` и имена ключей `Md.*` используют потребители — в
том числе через свой провайдер стилей и перекрытые ключи. Переименование, удаление и новый член
`IMdStyleProvider` ломают потребителя.

## Тема

- **Оформление — только ключами темы.** Шаблон берёт шрифт, цвет и отступ через `DynamicResource`
  на ключ `Md.<Блок>.<Свойство>`, а не литералом; стиль блока — `Md.<Блок>.Style`.
- **Всё, что нужно теме, достижимо из `Themes/Generic.xaml`:** потребитель вливает в ресурсы
  приложения только его.
- **Вложенная прокрутка отдаёт колесо наружу.** Блок со своим `ScrollViewer` ставит на него
  `NestedScroll.PassWheelToParent="True"`, иначе страница перестаёт прокручиваться, пока курсор
  над блоком.

## Ссылка сначала спрашивает приложение

Любой путь перехода по ссылке поднимает `MarkdownLink.NavigateEvent` и наружу открывает только
необработанную. Цель ссылки несётся исходной строкой рядом с `Uri`: разбор нормализует адрес и
портит свои схемы. Как этим пользуется потребитель — в [`README.md`](../README.md).

**Наружу вьюер открывает только адреса веба и почты.** Остальное — пути, файлы, чужие схемы —
открывает только обработчик приложения.

## Документ разбирается целиком

Markdig получает текст одним куском, без нарезки: ссылке по метке, сноске, пункту списка из
нескольких абзацев нужен контекст через пустую строку. Пустые строки исходника между соседними
блоками становятся отступами на любом уровне вложенности.

## Ничего не теряется молча

Блок или инлайн без своего вида не выбрасывается: у контейнера рисуется содержимое, у блока — его
текст, у инлайна — исходный кусок строки. Не рисуются только определения ссылок.

## Документ — виртуализируемый список блоков, а не `FlowDocument`

`FlowDocument` не виртуализируется.

## Своей прокрутки у вьюера нет

Вьюер ставят в чужую прокрутку: в `ScrollViewer`, в общую прокрутку страницы рядом с другим
содержимым, в виртуализированный список. Блоки виртуализирует `MdBlockPanel` по видимой области
всех прокруток-предков; без прокрутки вокруг создаются все блоки. **Панель блоков вьюера — только
`MdBlockPanel`:** стандартные панели в чужой прокрутке не виртуализируют.
